# stackchan-eyes

给 M5Stack StackChan（CoreS3）用的裸机待机固件：全黑屏幕上只有两只白色眼睛。

它不是循环播放表情，而是像一只待在桌上的宠物：大部分时间平静或专注地待着，
偶尔往别处看一眼，隔一阵有点什么情绪，慢慢地来，慢慢地走，困了会打个盹。
眼睛的画法和每个表情的数值来自 bloub。

没有操作系统，没有 FreeRTOS，没有 ESP-IDF，没有 Arduino，没有中断，没有堆。
一个主循环，每秒 60 次：推进动画，重画变化的部分，等下一拍。

## 现在设备上是什么

`build/eyes.bin`，22 992 字节，
SHA-256 `b8686cb4d57486aaae4ab5a9e379ca46a2c8da63a4d8ffe09331ea6956abc2c9`。
它是 `docs/stress-test.md` 里的「第 4 版」（上一版是 git tag `eyes-v3`）加上背光调节：
默认背光降到 2.7 V，串口可以按电压直接设背光（见下面的 `L` 命令和「亮度」一节）。
动画和渲染没有改，加上背光调节后没有重新压测。

它烧在 Flash 偏移 0，也就是原来二级 bootloader 的位置，占 32 KB 槽位的 70%。
芯片的 ROM 把它整个读进内存后直接运行。**原厂的应用、设置、资源分区一个字节都没动**，
所以还原只需要把原厂 bootloader 写回去。

## 常用命令

都在本目录下运行，默认串口 COM6。

```
python tools/fw.py build            编译，生成 build/eyes.bin
python tools/fw.py flash            编译并烧录
python tools/fw.py restore          还原原厂固件（写回原厂 bootloader）
python tools/fw.py monitor          看固件的串口输出，Ctrl+C 退出
python tools/fw.py log 10           重启设备并打印 10 秒启动日志
python tools/fw.py key i            向固件发送按键（见下表）
python tools/fw.py shot out.png     把屏幕显存读回成图片
python tools/fw.py sim              编译电脑端仿真器 build/sim.exe
```

编译器和 esptool 用的是 PlatformIO 放在 `~/.platformio` 里的那一套
（`toolchain-xtensa-esp32s3` 8.4.0、`tool-esptoolpy`）。

串口按键：

| 键 | 作用 |
|---|---|
| `i` | 屏幕状态、电池和供电、当前情绪和还会停留几秒 |
| `b` | 重放启动日志（电脑一般来不及看到第一遍） |
| `n` | 立即换成表情表里的下一个，0.7 秒到位。用来逐个看表情，压测也靠它 |
| `+` `-` | 背光电压加减 0.1 V（0.5~3.3 V，不保存，重启恢复默认） |
| `L2700` 回车 | 背光直接设成 2700 mV；`L0` 回车关背光。`tools/backlight.html` 用的就是它 |
| `s` | 把屏幕显存整屏读回并打印，约 6 秒 |
| `v` | 把屏幕显存整屏读回，与刚画的一帧逐像素比对，约 6 秒 |
| `t` | 测量屏幕开一个窗口、发一个像素各要多久 |

固件每换一次情绪会从串口打印一行 `expr 名字`，`monitor` 里能看到它这段时间经历了什么。

## 它怎么过日子

**两种休息状态**：平静（`neutre`）和专注（`attentif`），合计占约 78% 的时间。
平静时视线自在地游移；专注时看着正前方，游移减半，眨眼也少一半。

**小故事**：休息一阵之后，按权重抽一件「发生在它身上的事」，几个表情连着走完，
最后回到休息。表情不会凭空跳出来：生气要先经过怀疑，害怕要先经过惊讶，
睡着要先平静下来再犯困。同一件事不会连续发生两次。

**慢慢变**：换情绪的过渡是 2~6 秒（犯困 6 秒，平静 3.5 秒，专注 2.6 秒），
只有惊讶、害怕这类反应是 1 秒以内。曲线从静止起步，三分之一处最快，然后长长地收尾。

**往别处看**：在平静、专注、好奇、怀疑、困惑、无趣这几种情绪里，它隔一阵会转头看一眼别处，
停 0.7~3 秒再看回来；情绪本身就看着别处的时候（比如平静），这一眼有三成是看向正前方的人。
转头是 0.3~0.6 秒的快动作，幅度大时常常伴着一次眨眼。

**眼皮**：平时每 2~5 秒眨一次；犯困时眨得慢，眼睛会闭上一会儿才睁开；
睡着时眼睛是两道横线，随着呼吸轻轻起伏。开机时眼睛是闭着的，然后睁开。

电脑端 24 小时仿真（3 个种子）的统计：

| 项目 | 数值 |
|---|---|
| 平静 / 专注 | 约 50% / 约 28% 的时间 |
| 换一次情绪 | 平均每 27 秒；其中正在过渡的时间占 11% |
| 连续休息最长 | 4 分多钟 |
| 往别处看一眼 | 平均每 18 秒一次 |
| 打盹 | 平均 18 分钟一次，每次约 40 秒 |

## 可以调的地方

### 性格：`src/core/eyes.c`

`MOOD[]`，每个表情一行：

| 列 | 含义 |
|---|---|
| `settle_s` | 从别的表情变成它要几秒 |
| `stay_min_s` / `stay_max_s` | 变完之后停留多久 |
| `glance_s` | 平均多久往别处看一眼，0 = 不东张西望 |
| `wander` | 视线游移保留多少：1 = 发呆式的游移，0 = 盯住不动 |
| `lids` | 眨眼：正常 / 少眨 / 又慢又久（犯困）/ 不眨 |
| `gesture` | 1 = 一个动作而不是一种情绪（眨单眼），做完多快就收得多快 |
| `breath` | 呼吸时眼睛上下起伏的幅度 |

`STORY[]`，每行一件事：权重，然后依次经过的表情。头两行就是「继续平静」和「继续专注」，
**它们的权重决定它有多少时间什么也不干**；想让某种情绪多出现，加大那一行的权重，
或者加一行新的。

改完用仿真器看结果，不用上设备：

```
python tools/fw.py sim
build\sim.exe life 86400            过 24 小时，打印每种情绪占多少时间、出现几次
build\sim.exe life 1200 7 200 story 另外把前 20 分钟经历了什么逐条列出来
```

### 眼睛的大小和位置：`src/core/eyes.h`

| 常量 | 现值 | 含义 |
|---|---|---|
| `EYES_FACE_PX` | 400 | 设备正面的边长，按屏幕的像素密度折算（8 px/mm，5 cm = 400 px）。眼睛画在这个正方形的内切球上，所以它同时决定眼睛大小、间距和活动范围。改小，眼睛等比例变小 |
| `EYES_MARGIN_PX` | 8 | 眼睛离屏幕边缘至少留多少像素 |

屏幕是 4×3 cm，居中在 5×5 cm 的正面里，四周是黑的。眼睛亮起来之后看不出屏幕到哪里为止，
整块正面读起来就是一张脸。所以球按正面来定（半径 200 px），而不是按屏幕（旧版 136 px）：
眼睛大了 1.47 倍，和脸的比例与 bloub 里眼睛和身体的比例一致。
bloub 的两个身体形状正好夹住这个值：圆角方形对应 208 px，
胶囊（对应正面上屏幕能点亮的那条 5×3 cm 的带子）对应 192 px。
200 也差不多是屏幕容得下的上限：到 208，最大的那个表情（睁大眼）连同视线游移就放不进屏幕了。

黑边是眼睛去不了的地方。球上的位置如果会让眼睛出屏，就把**两只眼睛一起平移**回来，
间距、大小、倾斜都不变，等于把脸摆低一点或往里一点。这是 bloub 在胶囊形身体上的做法
（`eyefit.ts`）。19 个表情里只有 5 个需要平移：

| 表情 | 平移（像素，右 / 下为正） |
|---|---|
| 平静 `neutre` | −14，+45 |
| 兴奋 `excite` | 0，−10 |
| 害怕 `effraye` | 0，−30 |
| 无趣 `blase` | +12，0 |
| 睁大眼 `wide` | 0，−66 |

平移量在每次过渡的终点算一次，把视线游移的最坏情况算进去，过渡中在两个定值之间滑过去。
没有每帧去夹：那样眼睛一游移到边上就会贴着屏幕边缘滑，像贴在玻璃上。

把每个表情放在正面里看一眼：

```
build\sim.exe sheet <目录>                       每个表情一张图，并打印平移量
python tools/contact.py face <目录> faces.png    拼成一张总览，带设备正面
```

### 亮度

屏幕是 IPS 液晶，眼睛周围的「黑」是液晶挡住整片背光，挡不干净，所以黑底会透一点灰。
背光越暗，黑底越黑。背光没有 PWM，亮度靠电源芯片 AXP2101 给背光那一路（DLDO1）的电压，
0.1 V 一档。原厂固件的 1~100 对应 2.5~3.3 V；本固件允许一直调到 0.5 V，电压低不伤 LED，
只是低到一定程度背光就灭了。

`src/board/board.h`：`BOARD_BACKLIGHT_MV_DEFAULT`（现值 2700，原来相当于 2900）是开机背光电压。

现场调：用 Chrome 或 Edge 打开 `tools/backlight.html`，连上串口拖滑块，屏幕跟着变；
满意了把页面给出的那行 `#define` 写回 `board.h` 再烧录。用之前先关掉 `fw.py monitor`，
两者不能同时占串口。

## 和 bloub 的关系

眼睛的几何模型（画在球面上的胶囊、切平面投影、每只眼自己的倾斜、眨眼是屏幕上的
竖向压扁）和每个表情的数值，从 bloub 的 `face.ts`、`expressions.ts`、`engine.ts`
原样移植，并用 bloub 自己的引擎核对过（见 `docs/stress-test.md`）。

有意不同的地方：

- **没有身体**。整屏纯黑，只画眼睛，所以和轮廓有关的一切都不存在。
- **19 个表情**：bloub 的 16 个静态表情，它状态表里两个只动眼睛的状态
  （`wink` 眨单眼、`wide` 睁大眼），再加一个 bloub 没有的「睡着」（`endormi`）：
  两只眼都用 bloub 给眨单眼量出来的那个闭眼形状。
- **行为**。bloub 按剪辑播放；这里是上面说的那套情绪。
- **过渡曲线**。bloub 用 `1-(1-k)^5`，0.45 秒，起步就是全速。这里是
  `1-(1-k)^n·(1+nk)`：从静止起步、同样的指数收尾、同样不过冲，速度在 `k = 1/n` 处最大。
  换情绪用 `n = 3`，转头看一眼用 `n = 5`。
- **眼睛的大小和定位**：见上一节。
- **时间**：bloub 用绝对时间求值；这里每个振荡器自己累加相位，可以无限期运行而不丢精度。

## 目录

```
src/core/     表情、行为、抗锯齿光栅化。纯 C，不依赖硬件，电脑上也能编译
src/hal/      芯片：启动、时钟、看门狗、串口、GPIO、I2C、SPI 和屏幕驱动
src/board/    板子：电源芯片、IO 扩展、屏幕型号识别、身体控制器
src/main.c    主循环
ld/eyes.ld    链接脚本，全部放在内存里
sim/          电脑端仿真器，和固件跑同一份 src/core
tools/        fw.py（编译烧录）、stress.py（压测）、contact.py（把仿真画面拼成总览图）、
              bloub_ref.ts（取 bloub 参考值）、backlight.html（网页串口调背光）
docs/         压测记录
```

上一级目录（git 仓库根）里：

| 目录 | 内容 | git 里怎么放 |
|---|---|---|
| `bloub/` | 眼睛模型的来源，`tools/bloub_ref.ts` 用它核对移植 | 子模块，固定在核对时用的提交 |
| `StackChan/` | M5 原厂固件源码，对照寄存器和初始化序列用 | 子模块，固定在参考时的提交 |
| `backup/` | 原厂 bootloader 和部分 Flash 读出 | 不进 git |
| `_ref/` | 写驱动时对照用的 ESP-IDF 头文件和 M5 显示库源码（可以删） | 不进 git |

克隆后取子模块：`git submodule update --init`。

## 它对硬件做了什么

- 电源芯片 AXP2101、IO 扩展 AW9523 的寄存器写入与原厂固件逐字节相同，
  包括各路电压和充电电流（700 mA）。
- 屏幕初始化序列与原厂固件相同；按原厂的办法（读触摸芯片固件号）区分 ILI9342C 和 E。
- **关闭舵机供电**，头部不会被电机保持住，可以用手轻轻摆正。**关闭灯带**。
- 不碰 WiFi、蓝牙、摄像头、麦克风、喇叭、SD 卡、Flash。

## 需要知道的事

- **整片 Flash 备份决定不做。** 本固件只改写 Flash 前 32 KB，原厂 bootloader 已另存为
  `backup/factory_bootloader_0x0000-0x8000.bin`，`restore` 只需要它。`backup/` 里另有
  第一次烧录前读出的前 7 MB（`chunk_00` ~ `chunk_06`），用不到。`backup/` 不进 git，
  上面那个 32 KB 的文件要自己留好。真要补完整片备份：`bash ../backup/read_chunks.sh COM6`
  （从第 8 块续读，约 18 分钟）。
- **没有休眠也没有自动关机**，屏幕一直亮。它「睡着」只是表情，背光和芯片都照常工作。
  USB 供电没问题；只靠电池会一直耗到电源芯片自己断电。长按电源键关机靠的是电源芯片的
  硬件功能，本固件没有验证过。
- **它感觉不到外界**。触摸、麦克风、陀螺仪都没有接进来，所有情绪都是它自己冒出来的。
- 冷启动、长时间运行、电池供电、肉眼观感都还没测，详见 `docs/stress-test.md` 末尾。
- 设备卡死也能重新烧录：ESP32-S3 的下载模式在 ROM 里，`fw.py flash` 和 `restore`
  会通过 USB 自动进入（本次开发中每次烧录都是这样进的）。万一进不去，M5 的 CoreS3
  文档给的手动办法是长按复位键约 3 秒直到绿灯亮；这个办法我没有在这台设备上试过。
